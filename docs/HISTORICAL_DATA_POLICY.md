# 历史数据保存规则

用户于 2026-11-03 明确：历史数据校验无误后永久保存，不再自动刷新、重新采集或加工。

- 正式数据及验收证据保存在线数据库；本地回执只供审查。
- 完整验收通过后锁定数据版本、证券身份、时间范围、单位及证据。后续任务只读该版本，跳过对应采集与加工。
- 新增月份和未通过的历史缺口继续补齐；单个组件通过不代表整个年度已验收，不提前锁定未通过区间。
- 代码或供应商变化不能自动触发对已验收历史的重采、重加工或覆盖。若发现问题，记录问题并交由用户决策，不静默改写。
- 锁定校验失败不得使用强制参数放行。现有不可变证据和数据库锁守卫继续保留。

历史股权身份是独立验收项：IR / JCI 的当前年末报价可以核验，但不能据此批准另一股权的旧历史、跨合并/分拆收益或全年指数资格。在线身份证明及守卫版本进入缓存指纹，完整历史未验收时旧生成器不得沿用旧年度/曲线缓存绕过。相关检查在采集及写入前停止，原始数据、锁与产物保留；当前独立净值和排名不依赖旧历史任务。详见 [IR/JCI 审查](IR_JCI_LINEAGE_REVIEW_2026-11-05.md)。

SQL 120 将验收价格与证明中的实际来源绑定，支持接口原价 `eastmoney_native` 和发行人明确披露 `issuer_native`；旧证明继续绑定其原有来源，不重新选择。两类验收均禁止修改价格或回执，未支持来源拒绝放行。正式代码变更后自动运行影子验证，仅在临时表测试，不自动重新迁移或加工历史。

2026-11-05 补审：旧 `lock_symbols.py --lock` 仅依据月数、全收益标签和无大跳变创建锁，未验证身份、现金流和完整收益，现已移除写锁实现；旧命令在访问数据库前明确拒绝。定时任务改为只读 `--check`，仅报告覆盖初筛，不称作验收。已有锁不撤销、不覆盖；新增完整验收继续使用绑定独立证据的专用入口。

后续入口审查同步移除无调用方的 `relock.py`，禁止把漂移直接重哈希为新锁。`lock_stage.lock` 仅保留已存在的区间锁，不再凭初筛创建新锁；`--force` 无法放行。只读诊断不创建表。实际操作与边界见 [锁操作说明](LOCKING.md)。

`fill_yahoo_gaps.py` 仅计划非全收益、尚无该来源历史且未隔离/冻结/锁定的证券；完整历史请求遇到任一有效保护区间即跳过整只，不能靠写库触发器报错后才发现重采。请求前再次在线核对，检查失败不请求源。全局月份锁及撤销记录均参与判断。网络失败和时间预算留下未尝试项时返回失败，定时任务不再隐藏该步骤错误。这个整段历史入口不承担已保护证券的新增月份采集，新增数据由独立的有日期边界链路推进。
