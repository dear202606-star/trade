# 在线报价刷新

2026-11-04 起，页面报价直接读取 Supabase 的 `live_quote_snapshot` 单行快照，不再读取部署产物 `data/quotes.json`。公开角色仅可读；写入使用现有任务密钥。当前报价可更新，历史价格、选源和锁定记录不参与该链路。

`live_quotes.py --write` 从在线成分区间确定当前标的，复用现有报价字段校验。要求 SPY 存在、同一场次报价覆盖率至少 98%、价格和昨收及涨跌字段一致、源时间及时且时区有效、汇率有效；任何失败都不写新快照。重复内容及较早快照不能覆盖现值。接收时间保存在 `collected_at`，页面显示数据源实际报价时间，避免把重新抓到的旧收盘价标成“刚更新”。

`.github/workflows/quotes.yml` 使用独立的 `trade-live-quotes` 队列。工作日 UTC 13–21 时每 5 分钟触发，另有 UTC 02:17 的收盘后补采；页面可见时每 60 秒读取在线库。任务不重算排名、历史或策略曲线，不等待全量历史任务，也无需为每个报价部署网页。GitHub 调度时间可能延迟，5 分钟是触发目标。

`.github/workflows/ui-publish.yml` 独立发布网页。`publish_ui.py` 复用最近一次成功发布的 Pages 数据，核对线上 A/B 信号及净值，并保证全部数据文件的字节散列不变，只替换网页资源。生成目录为 `_site_release/`，不覆盖维护文档；发布包排除 Markdown 工程记录。没有可核对的发布快照时停止，禁止临时重算历史。

净值持仓的 `entry/last` 与源报价可能使用不同股份单位。日内金额现在将原始报价按 `last/last_raw` 转入净值单位；持仓日期必须与报价日相同，或在前一工作日且原始末价与源昨收吻合。单位或日期不明时不显示推断的日内收益。年度值只在衔接已验证时增加当日变化，持仓行同步使用同一批报价；已有同日净值不重复叠加，其他情况显示已结算日期。

已完成在线建表、公开只读及内容散列校验、重复/较早/缺 SPY 快照的实际事务回滚探测，以及正式网页与手机宽度确认。首个远端任务暴露本地口令文件依赖，已修正为优先读取现有环境密钥并完成真实远端成功运行。相关回执见 `output/live_quote_schema_applied.json`、`output/live_quote_online_verification.json`。线上 E2E 的报价检查也已改读同一在线库，读取失败不能靠旧文件通过。

仍需收敛：交易所休市及提前收盘日历、watchdog/realtime_check 对在线报价的完整切换，以及净值增量更新。当前报价对无当日场次或延迟过大的结果保留旧快照并报错；这不能替代全年交易日历验收。历史策略仍未完成整体数据验收，恢复报价刷新不代表所有策略收益已经验收。
