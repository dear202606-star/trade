## 执行顺序与收敛记录

本目标滚动纳入用户后续决定；更新目标时同步问题清单、依赖、完成条件及交接入口，不用新增文档掩盖过期结论。问题状态统一为未审查、已定位、修复中、待验收、已验收、已锁定或已清理；每次关闭问题都必须指向当前版本的验证证据。阶段提交、阶段发布与最终完成分别记录。

1. 以当前仓库、在线库及实际运行状态建立要素/依赖清单；核对既有结论的范围和时效，标记未审查、失败、局部通过、完整验收、已锁定。

3. 完成候选数据、排名、持仓及逐期收益的端到端审计。差异逐项解释，未决项交用户决策；不手工改正式 JSON 或放宽门槛制造通过。

6. 新增/变化先判断影响范围。已锁历史只读；未锁部分仅重做真正受影响的依赖。供应商或代码升级不能自动触发已验收历史的重加工。
7. 在对应依赖被新实现可靠替代、差异验收通过后，清理旧实现和无用对象；重新核查全部直接调用方、定时任务、文档及数据库依赖，避免删完后留下断链。阶段性无问题的范围及时提交、push，并按已授权范围迭代发布。

### 自动刷新管线专项验收

- **按期触发**：对照实际配置的交易日历、时区、触发频率及截止要求，留存连续运行记录；覆盖交易日、周末/休市、跨月/跨年及行情时段变化。延迟与漏触发可被检测，不能依赖人工发现和手动启动。尚未明确的时效要求必须确认，不能自定宽松标准后称达标。
- **真实更新**：记录源数据时间、采集时间、在线入库时间、计算和发布时间；以实际新增行、源版本、数据库版本和发布版本证明数据流转。时间戳更新或任务绿灯不能代替真实数据更新；非交易日合理无变化须有日历依据。
- **增量正确**：只采新增、确有变化或尚未验收的数据；已锁历史零重采、零重加工、零覆盖。变化检测必须覆盖价格、企业行动、证券身份、成分和行业等真实依赖，不能遗漏上游变化，也不能把无关变化扩散成全历史重算。
- **失败封闭**：超时、断网、限流、额度耗尽、空响应、部分写入、数据库/只读接口失败、校验失败及构建/部署失败均有明确状态和非成功返回。禁止静默回退到旧文件、将旧数据标成新数据、使用旧产物冒充本次成功。
- **安全恢复**：断点续跑、幂等和有界重试经实际验证；重复触发、并发、进程中断及任务被取消不能重复写入、重复计入现金流、覆盖锁定版本或发布混合快照。观测超时不能被误判为任务已停止。
- **发布一致**：部署前验证覆盖当前产物，发布后检查绑定实际部署版本；浏览器读取的数据与在线库认可的导出版本一致，刷新时间真实，失败不替换最近已验收版本，并具备可验证的回退路径。
- **可运维**：运行回执包含目标、实际处理量、跳过量、失败量、未尝试量及原因、阶段耗时和版本。已有告警/补偿机制必须实测，确认失败可达、恢复可确认，不只记录日志而无人获知。

每项均须有对应实际运行、故障注入/回滚或重放证据，并注明未覆盖场景。不能只用 mock 测试证明生产管线可靠；正常、失败、恢复三条路径都必须验收。
