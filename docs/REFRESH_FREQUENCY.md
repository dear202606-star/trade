# 实盘数据刷新频率

2026-11-03 用户授权自行评估并合理设定。

## 设定

- 浏览器可见时每 60 秒检查新行情；维持现有设置，不以轮询次数冒充数据更新次数。
- 盘中后台行情更新目标为每 5 分钟一次。闭市后进行收盘校验；休市期间不无意义高频抓取。历史已验收数据保持只读。
- 盘中行情超过两个目标周期仍无有效更新，应进入陈旧/失败状态并被监测发现；该要求须按源时间和交易日历判断，不能只看文件生成时间。
- 日期与时段须按交易所日历及 America/New_York 时区判定，不能将固定 UTC 小时窗直接等同于美股交易时间。

## 本次实查与限制

在线 cron.job 只读查询确认：trade-dispatch-market 为 */5 13-21 * * 1-5，已启用；trade-dispatch 为 20 */2 * * *，已启用。前端 page.js 当前轮询间隔为 60000 毫秒。

现有 5 分钟任务派发的是完整行情/策略/构建流水线，与较长的排名、历史计算共用并发组。触发频率不等于实际更新频率；尚未实现或验收 5 分钟端到端更新承诺。后续必须拆出只处理当前行情和受影响估值的轻量路径，避免重采、重加工已验收历史，并验证并发、故障恢复、源数据时刻和发布延迟。盘前盘后覆盖及完整交易日历也需验收。

GitHub Actions 原生定时任务最短间隔 5 分钟，且可能延迟或漏触发。免费行情源的实际延迟和请求额度尚无稳定性保证，不能把更密集轮询说成更快的真实数据。

- https://docs.github.com/en/actions/reference/workflows-and-actions/workflow-syntax
- https://docs.github.com/en/actions/how-tos/troubleshoot-workflows

在现有部署架构下选择 5 分钟作为盘中目标，不承诺秒级行情。若实测端到端耗时或来源限额不满足，先修管线并保留真实新鲜度，不靠加大触发次数掩盖延迟。
