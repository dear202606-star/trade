# 选中价格指纹修复

旧 `db_prices._db_stamp` 及 B 历史输入指纹依赖价格总和，后者还只保留两位小数。PostgreSQL 临时影子数据复现：A/B 两行价格从 10/20 互换为 20/10，行数、最大采集时间、证券数及价格总和不变，旧版本号完全相同。仅修改原价、来源或口径也可能漏检。这可能使旧结果或读取期间变动未被识别。

现在两处复用同一数据库指纹：按证券及月份排序，对包含证券、月份、复权价、原价（含空值）、来源和口径的 JSON 行计算 SHA-256。物理行顺序不影响版本；不再将网络失败转换成可复用的输入版本号。此项不改动在线价格、选源、成员、锁或旧基线，也不解除历史身份未验收的限制。

`research/verify_selected_fingerprint.py` 在同一事务的临时对象中执行正式指纹 SQL，验证等总和价格互换、仅原价变化、原价空值替换、来源、口径、证券、月份、小于旧舍入单位的价格变化都会改变指纹，物理行重排保持相同；事务最终回滚。共 9 项通过，见 `output/selected_fingerprint_verification.json`。已将真实数据库探针加入正式身份防护任务；单元回归另验证断库必须停止。工程全套 258 项本地测试通过。
