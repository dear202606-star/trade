# 数据分层与锁定机制

> 目标：**历史层异步补齐后逐段锁定，永不重抓**；**当年持仓层尽量快**，准且新。

## 一、两层架构

| 层 | 范围 | 更新方式 | 存储 | 锁定 |
|---|---|---|---|---|
| **历史层（frozen）** | 2010-01 → 上一个完整年度 | 异步补齐（每天若干只），补齐后**逐段锁定** | `prices_monthly`（DB） | 锁后禁止写入，禁止重抓 |
| **当年层（hot）** | 本年度至今 + 实时行情 | 盘中每 5 分钟；行情有就更新 | `prices_monthly`（当年月份）+ `quotes`（实时） | 不锁，年底整体结转 |

## 二、锁定机制（数据库级强制）

```sql
locks(kind, scope_from, scope_to, status, rows, symbols, hash, locked_at)
```

- 触发器 `guard_locked_months`：一旦 `locks` 里存在 `status='locked'` 且 `scope_to >= 新行 month`，
  对 `prices_monthly` 的写入**直接抛异常**：`month 2020-03 is locked (frozen through 2025-12)`
- 锁定前必须过校验（`lock_stage.py --check`）：
  1. 区间有数据
  2. 12 月行数 ≥ 年数 × 400
  3. **全收益口径占比 ≥ 80%**
- 锁定记录内容哈希（`md5(string_agg(...))`），任何改动都会被发现
- 修复历史必须新建锁版本（`scope_from/scope_to` 不同），不能改旧锁

### 当前状态（2026-10-31）

```
区间 2010-2025：158,410 行 / 845 只 / 12月 13,303 行 / 全收益 5,201 行（3.3%）
✗ 未通过：全收益口径仅 3.3%（要求 ≥80%）
```

**所以历史层暂不锁定**，等 Yahoo/AV 把 `price_only` 全部转成 `total_return` 后再锁。

## 三、为什么必须「先全收益再锁」

`price_only`（仅拆股复权）缺分红，对高股息股低估 1–4%/年，会系统性改变年度动量的排名。
锁定等于承诺「这批数字不再变」，口径不纯时锁定 = 把错误固化。

## 四、当年层（hot）的时效设计

| 环节 | 现状 | 目标 |
|---|---|---|
| 行情抓取 | Supabase 盘中每 5 分钟触发 quotes.yml | 保持 |
| 行情→页面 | 抓取→构建→部署约 2–4 分钟 | 保持，CDN 600s 缓存是主要延迟 |
| 前端刷新 | 每 60 秒重拉 quotes | 可降到 30 秒 |
| 数据完整性 | 抓取后校验：价格>0、涨跌幅合理、覆盖率 ≥95% | 已在 selftest |

**当前持仓的实时表现**不依赖历史层：`equity.py` 只用「建仓价 + 最新价」，两者都在当年层。
所以历史层锁定/回填不会影响盘中数字。

## 五、操作手册

```bash
# 查看锁定状态
python lock_stage.py --list

# 校验某区间是否可锁（不改数据）
python lock_stage.py --check 2010,2025

# 锁定（校验不通过会拒绝；确认可接受才加 --force）
python lock_stage.py --lock 2010,2025

# 追加当年月份（解锁区不受影响）
python relay_source.py --symbols 50
```

## 六、流水线各环节的校验（采集 → 加工 → 存储 → 分析 → 展现）

| 环节 | 校验 | 位置 | 失败行为 |
|---|---|---|---|
| **采集** | 结构/连续性/异常月/口径/与库内交叉 | `ingest_validate.check_payload` | 整条拒收，打印原因 |
| **存储** | 唯一键、锁区间保护、basis 一致 | DB 触发器 + 约束 | 抛异常，不静默写入 |
| **加工** | 持仓 3 只、权重和 1、行业 ≤60%、逐年 3 只 | `selftest.py`（85 项） | 阻断部署 |
| **分析** | 累计=逐年复利、曲线末点=累计、基线年份集合 | `selftest.py` + `audit_b.py`（180 项） | 阻断部署 |
| **展现** | 页面值 = 数据值、区间口径、缺失显示 — | `consistency_check.py`（25 项/口径） | 阻断部署 |
