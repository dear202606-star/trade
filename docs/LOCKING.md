# 历史数据与锁的操作边界

当前规则见 [项目目标](PROJECT_GOAL.md) 与 [历史保存规则](HISTORICAL_DATA_POLICY.md)。覆盖率、全收益标签、无大跳变或旧指纹相同，都不能替代证券身份、日期、单位、企业行动、现金流和收益的独立验收。完整年度最终验收尚未完成。

## 既有锁保留

在线 `data_lock` 保存历史锁及撤销链；`locked_symbols` 是有效标的锁的兼容视图。旧 `locks` 区间记录继续只读保留。锁与冻结选源的数据库守卫必须保留；不能因程序报错而解除保护，也不能自动修改旧指纹来使检查通过。

2026-11-05 只读盘点：有效 `symbol_month` 锁 962 条，范围均为 2012-01 至 2025-12，指纹算法为 `sha256-16`。这是已有锁清单，不是重新授予这些数据完整验收。

## 只读检查

```bash
python lock_symbols.py --check
python lock_stage.py --list
python lock_stage.py --check 2010,2025
python verify_locks.py
```

前两种覆盖检查仅作初筛。`verify_locks.py` 比对当前选中序列与旧指纹；选源、身份边界或数据变化都可能产生差异，必须调查。指纹一致不证明原始数据语义正确；抽样成功不能冒充全部锁检查。

## 移除错误放行路径

- `lock_symbols.py --lock` 在数据库访问前拒绝，定时任务已改为只读检查。
- `lock_stage.lock` 只允许确认并保留已有锁；不存在既有锁时返回失败，不创建新验收。覆盖检查通过和 `--force` 均不能绕过。
- 已删除无调用方的 `relock.py`。它曾将现存锁作废并用当前序列重建指纹，且默认处理 AAPL/MSFT；不得把这种行为当作数据修复。
- 只读诊断命令不再创建表或修改守卫。数据库结构由 SQL 迁移管理。

新增完整验收必须绑定独立证据及明确范围，使用相应专用验收入口。已锁历史若发现错误，先保存差异和影响，经用户决策后设计明确的新版本，不静默覆盖或自动解锁。

## 增量运行

完整历史补数遇到任一有效锁或冻结时跳过，不请求来源。新增日期由有明确日期边界的链路处理；跳过历史不等于新增数据已补齐。当前净值、排名与行情使用独立在线链路，详见 [动态链路审查](../_archive/2026-11-06/docs/LIVE_DEPENDENCY_REVIEW_2026-11-05.md)，不依赖 Pages 发布或重跑往年历史。
