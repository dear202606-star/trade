# 技术架构

> 版本 v3.0 ｜ 2026-10-29

## 1. 总览

```
┌─────────────────── 调度层 ───────────────────┐
│ Supabase pg_cron + pg_net                    │
│  · 盘中（13–21 UTC，工作日）每 5 分钟         │
│  · 其余每 2 小时                              │
│      ↓ workflow_dispatch（带 PAT）            │
└──────────────────────────────────────────────┘
                     ↓
┌─────────────────── 计算层（GitHub Actions）──┐
│ quotes.py          行情快照（508 只）          │
│ monthly_pick.py    信号（同月增量 ~20s）       │
│ equity.py          当期净值（日频）            │
│ strategy_history.py 16 年记录（锁定后 1s）     │
│ site_build.py      构建 8 个静态文件           │
│ selftest.py        48 项硬校验（不过则不部署） │
└──────────────────────────────────────────────┘
                     ↓ 提交并部署
┌─────────────────── 展示层 ───────────────────┐
│ GitHub Pages（静态 · 单页 H5）                │
│ docs/data/*.json → page.js 渲染五个区块        │
└──────────────────────────────────────────────┘
```

**无后端**：所有计算在浏览器用页面内 JS 完成，JSON 只提供数据。这样可以零运维成本，
也避免了"服务挂了页面就白屏"。

## 2. 组件职责

| 文件 | 职责 | 关键约束 |
|---|---|---|
| `market_data.py` | 双源抓取（新浪/Yahoo）、拆股复权、质量隔离 | Yahoo 不可达时降级为单源并记录 |
| `datafeed.py` | 缓存、时点成分表、行业、统一复权入口 | `load_bars` 三级回退：缓存→面板→实时 |
| `quotes.py` | 生成 `quotes.json`（价、昨收、涨跌、交易日） | 覆盖率 <80% 时告警 |
| `monthly_pick.py` | 排名、行业约束、权重、锁定 | 只用**排名日的时点成分股**；同月增量 |
| `equity.py` | 当期净值、持仓、账户口径 | 满仓 gross，不按敞口缩放 |
| `strategy_history.py` | 16 年回测、逐年明细、曲线 | 锁定后不重算（1 秒返回） |
| `dashboard.py` | 历史信号页（已并入单页，保留生成能力） | 不重复主页面信息 |
| `site_build.py` | 组装页面、注入导航、版本号 | 静态资源带指纹 |
| `selftest.py` | 部署前门禁 | 48 项，任一失败则不部署 |

## 3. 数据流

```
新浪/雅虎日线
   ↓ 复权（output/splits.json，合并写入）
月线聚合
   ↓ 排名（时点成分表过滤）
年度前 3 + 行业约束 + 权重
   ↓ 锁定（official_locks.json）
signal.json ──┬─────────────→ 首页/策略页/账户页
              └→ equity.py → equity.json（当期净值 + 持仓）
                              ↓
                         页面计算账户（1万/10万/100万）
```

## 4. 关键设计决策

| 决策 | 原因 |
|---|---|
| 历史回测一次算完并锁定 | 每次运行重算要 118 秒且可能因数据修订漂移；锁定后 1 秒返回 |
| 持仓在换仓日锁定 | 防止事后补录（未来函数），`official_locks.json` + 自检门禁 |
| 用时点成分股而非当前成分 | 当前成分含未来纳入的股票（LITE 2026-03 才入指，曾因此选错） |
| 账户是"理论账户" | 不做用户系统；所有人看到同一组数字，避免各自成本价造成口径分裂 |
| 页面内计算而非预渲染 | 本金切换（1/10/100 万）线性缩放，预渲染会产生 3 套数据 |
| 红涨绿跌 | 大陆用户习惯，与欧美相反 |

## 5. 失败模式与降级

| 失败 | 表现 | 当前处理 | 风险 |
|---|---|---|---|
| Yahoo 不可达 | 双源核对跳过 | 降级单源，日志记录 | 🟡 拆股漏检（见 KNOWN_ISSUES G1） |
| 新浪缺票 | 覆盖率下降 | 覆盖率 <50% 则失败 | 🟡 隔离票静默移出排名池 |
| 拆股未登记 | 收益断崖 | `splits.json` 人工维护 | 🔴 无自动检测门禁 |
| 历史锁定不一致 | 自检失败 | 阻断部署 | 🟢 |
| 持仓漂移 | 自检失败 | 阻断部署 | 🟢 |
| 数据过期 | 页面提示"数据偏旧" | 26 小时阈值 | 🟢 |
| Actions 失败 | 站点停更 | 无主动告警 | 🔴 见 KNOWN_ISSUES B3 |

## 6. 可观测性

- `docs/data/quotes.json`：`ok` / `coverage` / `stale[]` / `count`
- `docs/data/equity.json`：`updated`（北京时间）/ `points` 末点
- 页面：净值时间戳、`⚠ 数据偏旧` 提示
- 自检：`selftest.py` 输出通过项与失败项

## 7. 演进方向

数据库作为唯一事实来源（详见 [ARCH_PLAN](ARCH_PLAN.md)，分支 `db-arch`）：

- 锁定层（成分/公司行为/月线/年度选股/历史净值）一次写入并禁改
- 变动层（行情快照/当期信号/当期净值）幂等 upsert
- 审计层（`run_log` / `signal_ledger` / `quarantine_ledger`）保证可回溯
